# Real application assessment readiness v0.1

Use Application Authorization → Start guided application mapping. Save an explicitly owned LOCAL 127.0.0.1 target and three distinct actor contracts. Save secrets only through the credential vault; no headers or sessions belong in offline exports or case packets. Inspect assessment readiness to read saved authority, actor declarations and the selected exact native map without contacting the target. This read requires credentials.readSummary and organization membership; it grants no execution authority.

The checklist distinguishes missing profiles, declarations, native verified actor/route pairs, stale/unknown evidence, optional minimized intake, human policy review and separately approved proof. Scope registration is an owner declaration. It is never permission for automatic scanning. Readiness is a point-in-time snapshot, not approval and not a security verdict. Select the exact retained map and saved profiles; changing selection discards late responses. A rotated/revoked profile or changed source cannot restore authority through readiness.

For producer/consumer relationships select already observed identifiers, references and separate version fields. Optionally select an already observed producer owner field, an actor and explicit non-secret principal/tenant declarations. Exact native identity and typed resource owner/tenant must corroborate those declarations. Conflict, absence, bad source binding or an unobserved owner field abstains. The owner, same-tenant nonowner, other-tenant and anonymous contexts aid policy review; none establish legitimate access. Each allowed actor-visible producer owner field must also match the declared owner. A different or missing owner remains explicit counterevidence and prevents promotion of that actor relationship; existing typed-state positive-control and native proof safeguards still apply. Matching references do not prove causation, a database snapshot, transaction completion or policy correctness. Existing human review, immutable plan binding, authorization and bounded native GET proof remain mandatory.

Inspect the analyst case brief after proof: observation source, exact reviewed checks, remaining uncertainty, comparison completeness and next action. Export the redacted packet with exact history indexes and source hash; inspect the complete comparison history before resolving a case. Notes do not suppress findings. COMPLETED, UNKNOWN, untested and incomplete evidence never imply whole-application acceptance. Proposed owner inputs are human declarations; only executed native checks are proof within their reviewed contract.

Numeric owner policy inputs accept explicit finite JSON decimal syntax, including zero and exponents, and preserve invalid text for correction. Whitespace, hexadecimal and nonfinite conversions cannot silently become identity zero. Readiness and policy review do not bypass existing positive-control matching.
