# Observed-State Regression & Continuous Assurance v0.1

## Operator workflow

In Application Authorization, open **Observed-State Regression & Continuous Assurance**. Select a reviewed transition matrix whose current native baseline matches every declared role/object/tenant/state expectation. Supply a purpose and an exact numeric revision-marker path for each route. Preview the actor-specific policy, save an immutable version, then confirm the authority key trust and exact policy expectations. Changed versions require another explicit review; approval of a successor supersedes the prior version without rewriting it. Revocation is append-only.

Provide a current authorization reference and SHA-256 binding to create and review a manual observation-only Continuous Assurance policy. It evaluates retained later native maps; it does not collect observations or queue target requests. Blank source selection uses the newest later revision including incomplete revisions. It never falls back to an older healthy observation. Manual, schedule and deployment triggers share existing CA runs, leases and notification history. Schedule/deployment configurations need a separate exact policy review through the existing workspace/API. The new form defaults both automatic triggers OFF.

Open immutable assessment history to inspect actor/route decisions, expected typed fingerprints, later markers, source IDs/hashes and native comparison IDs. Scope labels distinguish observed-policy conformity, read-only access findings and **state-change authorization NOT_TESTED**. Findings, Recovery and Continuous Assurance expose the same scoped review alerts. Refresh attention to reload changes made by other sessions; completing an assessment refreshes the current panel automatically. Acknowledgement does not erase evidence or establish restoration.

## Outcome contracts

- MATCHED / observation-only PASSED: every comparable cell matches the explicitly reviewed policy. It is not a full application pass, transition authorization proof, causal proof or confirmed vulnerability.
- DRIFT / REGRESSION: a classified access decision or exact typed business state differs for a proven actor/object/tenant and unchanged revision marker. Warning requires human review, with immutable evidence. No automatic finding creation.
- INCONCLUSIVE: missing positive controls, revoked/superseded policy, incomplete/cancelled acquisition, stale/older selection, missing identity, wrong object/tenant, changed role/credential, changed revision, source custody/authority failure or unusable comparison. Nonquiet, no guessed secure outcome.
- UNTESTED: no selected assessment/policy or state hidden behind a denial. A denied read can match an access expectation while its business state is NOT_OBSERVED_DUE_TO_DENIAL.
- Unresolved cleanup blocks a passing gate; UNKNOWN worker/deployment blockers remain authoritative. Observation analysis cannot dispatch, recover, clear quarantine, replay or purge.

Numeric revisions are retained only as typed hashes. Equality is tested; numeric ordering, monotonicity and transition causality cannot be inferred. Current source bindings and immutable review semantics are revalidated at assessment time. Algorithm v2 refuses old v1 transition admission while preserving history.
