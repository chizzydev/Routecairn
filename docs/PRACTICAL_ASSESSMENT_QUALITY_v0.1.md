# Multi-application Practical Assessment Quality & Operator Onboarding v0.1

## Product workflow

Start in Application Authorization → guided mapping → set up an owned application. The four keyboard-selectable setup steps cover exact local scope and owner explanation, three disposable actors, explicit non-secret JSON marker paths, and the review of declaration status and observation cost. Advanced details remain editable. Save only creates encrypted declarations in one database transaction; it sends zero target traffic and grants no execution authority. An 8-request initial observation (identity/control plus four actor cells) still needs its own immutable review and explicit approval. Generated hypotheses are questions, not proof or inferred owner policy.

Edits invalidate pending onboarding selection. An obsolete response can reflect a real server commit: the UI clears entered credentials, does not select that target, retains the edited metadata and tells the operator to inspect inventory before retrying. It neither deletes that commit nor automatically retries. Unmount also invalidates completion callbacks. Failed saves expose no backend diagnostics and clear credentials. Network uncertainty is never proof of rollback.

## Application intelligence

Observed-link algorithm v2 extends existing bounded passive response analysis to concrete JSON:API/HAL named string links and HTML head next/previous advertisements. All original same-origin, literal path, GET, 8 KiB, 32-link, depth and truncation gates remain. Queries, encoded or ambiguous paths, base overrides, non-GET links and off-origin destinations are not followed. Route shapes identify observed numeric/UUID segments for human inspection only; exact source-bound URLs are unchanged. Advertised actors are witnesses, never inferred access policy. Older v1 response evidence cannot be silently relabelled v2; a fresh native observation is required to use the new analysis contract.

Two fresh synthetic Python stdlib HTTP/SQLite presentations exercise SQL-backed authorization, server-rendered navigation, JSON:API relationships, path parameters and role/tenant controls behind an owned recording gateway. This adds a real Python data/routing implementation to the earlier Node domain models. It does not constitute two independent frameworks or independent authorship. Every fixture is Codex-authored and known to its author. Full native observations, existing hypotheses, human-declared policy and normal workbench proof are reused.

## Reproducible benchmark intake

PracticalAssessmentBenchmark wraps the existing scorer. The public strict manifest commits source/oracle bytes, fixed application/case membership, request/source/route denominators and 2–10 repetitions. Optional independently pinned Ed25519 publisher signature verifies bytes only. It cannot establish oracle independence or blinding. Independent acceptance remains HOLD pending separately controlled provenance and review.

Use an exclusively owned output directory; commands refuse to overwrite existing outputs. With existing dependencies, no installation:

```powershell
node --import tsx scripts/practical-assessment-benchmark.ts commit PUBLIC_MANIFEST EXPECTED_MANIFEST_SHA256 repeat_1 MEASUREMENTS OUTPUT_COMMIT
node --import tsx scripts/practical-assessment-benchmark.ts score PUBLIC_MANIFEST EXPECTED_MANIFEST_SHA256 OUTPUT_COMMIT PRIVATE_ORACLE OUTPUT_SCORE
node --import tsx scripts/practical-assessment-benchmark.ts summarize PUBLIC_MANIFEST EXPECTED_MANIFEST_SHA256 COMMIT_ARRAY PRIVATE_ORACLE OUTPUT_REPETITIONS
```

Commit mode has no oracle argument and does not open the private key. Keep the private answer file with its independent custodian until all prospective predictions are committed. Missing apps/cases/runs remain UNTESTED. Known-truth abstentions are never TN, and unknown truth is not a negative. Repeat summaries expose every outcome, instability, false-positive review items and full fixed opportunities. There is no aggregate generalization claim or trusted-clock claim. Current local fixture policies are author-known; these runs are engineering reruns, not untouched blind holdouts. Parent-process CPU excludes workers and is explicitly labelled cumulative in the local measurement receipt.

## Windows evidence and limits

Original 30-second tests and 20-second native waits are unchanged. New fixture phase timing and an opt-in IPC-type-only observer distinguish bootstrap/runtime readiness, accepted work and root exit without logging payloads. Private V8 cache experimentation and all failures are retained; tsx disk cache stays disabled because its maintenance can delete files. A later combined three-test pass is not a causal fix for earlier timeout failures. Read the current TEST_MATRIX and raw selected combined run, not a union of isolated passes.

No full-suite, production, novice-usability study, independent oracle, release or Linux acceptance is implied. All existing operational HOLDs remain. No external target, automatic mutation, cleanup reset or Trusted Discovery activation was introduced.
