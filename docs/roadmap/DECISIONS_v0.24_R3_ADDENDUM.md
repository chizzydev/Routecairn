# v0.24-R3 roadmap decisions

1. Reuse native API policy matrices and registry authority; do not impersonate fixed v1 slots to claim registry compatibility.
2. Make exact resource policies available in the canonical dashboard, including useful two-account ownership checks and one-account field/session workflows.
3. Preserve the original collection algorithm and legacy role semantics; distinguish registry-bound principal evidence explicitly.
4. Treat redirect destination scope and credential-use consent separately. Stop cross-origin forwarding of supplied material; arbitrary header names may contain API keys.
5. Preserve authenticated split-origin and expiring HTTPS browser holds until their missing invariants have independent native acceptance. Refusal is not positive authentication proof.
6. Retain raw failures and source pins. Synthetic conformance, selected combined regressions, source verification, independent acceptance and production readiness remain distinct.
7. Source-first GitHub backup plus one lean review ZIP in Downloads governs delivery. Never recursively copy private databases, browser profiles, prior ZIPs or complete source snapshots into the review packet.
