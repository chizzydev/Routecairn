## Operator journey

1. Register an OWNED LOCAL 127.0.0.1 target with approved GET scope, and three distinct scoped vault identities with principal, tenant, role and identity-verification contracts.
2. In Application Authorization > guided mapping, select target/actors. Upload a local OpenAPI JSON file and inspect suggestions. This persists an immutable, sanitized schema summary and raw-input SHA-256, never fetches a server/ref, and sends zero requests to the application.
3. Choose at most eight candidates, enter concrete path arguments, select non-secret identity/tenant marker paths, review kind. Excluded methods are displayed and confer no authority. Route edits/removal return to manual declarations. Imported schema and concrete selections bind the fresh review digest and native job admission.
4. Confirm exact GET handlers are non-mutating, inspect all exact intents, then separately authorize observation. Existing scope/DNS/session/identity/worker/one-use/budget limits apply: 40 shared requests, 32 checks, concurrency one, 8192-byte module cap, 10-minute unused review expiry. A consumed ambiguous dispatch stays UNKNOWN without replay.
5. Inspect native map, enter typed expected object/tenant values and actor policy, review existing authorization matrix, separately approve proof. Findings and remediation use existing views and ScanComparisonService. Wrong-object HTTP200 and missing ALLOW controls never corroborate a finding.
6. Open retained maps. Create a read-only comparison against an explicit baseline: immutable paired revision/source hashes, declared added/removed seeds, observed access/response changes, selected marker types. Missing/unobserved cells are UNKNOWN; declaration changes are not discovered endpoint removal. Every difference is a hypothesis, never a finding or automatic regression gate. Opening old maps does not authorize new traffic; reconfirm before a fresh review.

## Supported REST subset V1

OpenAPI 3.0.x and 3.1.x JSON only; no YAML conversion or remote schema loading. UTF-8 <=262144 bytes; <=24 structure levels, 20000 nodes, 128 paths, 256 operations, 16 suggested scalar fields per candidate. Exact ASCII paths <=200 chars, <=4 unique path slots with required string/integer declarations. Parameters may use bounded local #/components/parameters/Name refs; response 200 application/json object properties may use bounded local #/components/schemas/Name refs. No external, escaped, arbitrary or cyclic reference resolution; <=8 ref hops, <=8 marker field segments. Integer concrete IDs use canonical nonnegative <=15-digit syntax. No encoded/traversing/query/fragment/empty path segments. Inline object scalar markers support string/number/integer; arrays/unions/composed schemas are not expanded. writeOnly, x-sensitive and password/binary/byte fields and secret/prototype field paths are excluded.

Root servers are ignored and never used as authority. Per-operation/path servers, callbacks, GET bodies and required non-path arguments are excluded. All non-GET operations are excluded. Unsupported response schemas can yield no suggested markers and require a manual declaration. Import is not a complete OpenAPI validator, reachability claim, crawler, or policy inference engine. Duplicate JSON object names follow JSON.parse last-value semantics; the exact source bytes are hashed. Description/example/default/security content is never executed or retained in sanitized summaries.

## Read permissions and immutable evidence

All workbench/mapping list and detail reads containing actor metadata require scans.read + credentials.readSummary + organization read membership. Advanced detail parity fixed from actual authenticated VIEWER HTTP200 RED to HTTP403 GREEN. ANALYST/OWNER may read; selected-organization missing resources return404, unauthenticated requests401. GET is CSRF independent. Ordinary scan views remain available to VIEWER. Schema import requires imports.create + credential summary authority + target resources.use; comparison creation needs comparisons.create/read + credential summary authority and organization read, grants no target execution. Native observation still requires scans.create, credentials.use and selected target/credential resources.use with ordinary session/CSRF checks.

Schema revisions and map comparisons have no-update/no-delete SQLite triggers (migration51). Comparison captures both maps and current target/credential context in one immediate transaction. Fresh comparisons require identical target/organization/actor/scope context and retained native reports where present; stale authority is refused. Stored comparisons remain historical snapshots, not evidence that current credentials remain valid. Native artifact hashes and completion checks are rechecked at capture. Incomplete reports refuse capture; unfinished/unacknowledged maps yield UNKNOWN. Later imports cannot rewrite earlier approval, selections, findings or comparison snapshots.
