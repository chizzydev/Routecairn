Product boundary
Trusted Discovery is a discoverable dashboard navigation view for retained local
candidate review and historical pre-consent. The shipping Execute (unavailable)
control is disabled and explained. No HTTP execute route, new enabling option,
production witness bootstrap, reset, reconcile, CLI flag or external activation
exists. Preview remains OFF by default, server-mode/local-control-plane only.
An enabled preview is not native execution authority. Stage B remains unchanged.

Routes and evidence flow
Existing POST /api/trusted-discovery/review and POST /api/trusted-discovery/pre-consent
are unchanged. Two new exact GET routes are intercepted before Stage A routing:
GET /api/trusted-discovery/status
GET /api/trusted-discovery/candidates/:scanId (exact UUID path; no query string)
All other namespace paths and methods retain ordinary authentication and404.
All privileged discovery JSON uses cache-control no-store. Unknown path labels
retain the existing sanitized telemetry template. No review token is a URL.

Status and candidates require the actual native cookie session, selected explicit
organization header, current OWNER account, live session/version/timestamps,
unlocked account, current password epoch, ACTIVE organization and OWNER membership.
The existing native cookie lookup returns that session's current CSRF hash;
read-only additional live checks use it privately, never a caller principal/role.
GET does not require mutation consent/CSRF; both existing POSTs retain original
CSRF/Origin/cookie/body and recaptured source/tenant authority enforcement.
Cross-site fetch metadata is refused. Client role labels grant no privilege.

Status projects up to64 authorized registered anonymous local target IDs and64
completed DASHBOARD scan IDs, with conservative generated labels and truncation.
Target URLs, owner-supplied display text, report paths, credentials, headers,
private tokens, exceptions, witness identities and report bodies are not returned.
Candidate projection uses the existing TrustedDiscoverySource canonical retained
2MiB report capture and current row/file fingerprints, plus the real planner.
Incomplete/invalid planner evidence refuses. Candidate IDs and ordinal labels
are projected only for conservative anonymous unobserved primary-origin GET
metadata. Unsafe query/fragment/object/auth/mutation-ish routes are omitted.
Up to64 projected candidates and48KiB JSON; no context, dispatcher, witness,
attempt, consent or transport is constructed by these read-only projections.
The original review rederives all eligibility and authority at mutation time.
An empty list is not an assertion that the target has no undiscovered routes.

Human-visible states
Preview is OFF or unavailable in this dashboard mode. Execution is unavailable.
Owner-only preview available. Selection alone does not send a request.
Review complete - awaiting deliberate historical pre-consent; no HTTP GET sent.
Pre-consent recorded - NOT EXECUTED. No HTTP GET was sent.
Review expired or invalidated; choose a fresh retained scan/review.
Request interrupted - outcome UNKNOWN; review/pre-consent may have been recorded.
Execution unavailable; deployment and independent witness custody require review.
Attempted - zero wire initiation (irreversible possibly-spent; not wire proof).
Native request initiated - inconclusive (native onRequestStart fact).
Response observed (status fact only; no vulnerability assessment).
Outcome persistence COMMITTED or UNKNOWN (signed evidence state, not a finding).
Cleanup FAILED/UNKNOWN or custody UNKNOWN - unavailable; investigation required.
Fixed allowlisted denial copy handles400/401/403/404/409/413/503 and unknown
transport failures. Raw socket, SQLite, filesystem and server exception text
is never rendered. There is no resend, retry-GET, cancel/refund or auto-confirm.
The pure native-facts renderer has no shipping result adapter. Only test-owned
typed adapters exercise native result presentation; no live execution is implied.

Transient state and accessibility
The exact safe returned review object, not a client URL, is used once with the
exact deliberately typed phrase I_CONFIRM_ONE_ANONYMOUS_NON_MUTATING_LOCAL_GET.
Review/confirmation/digest remain React memory only and are cleared after response,
expiration, target/scan/candidate change, organization switch, logout/session loss,
navigation/back-forward/hash, connection changes, hidden document, reload/unmount.
Generation checks reject stale async responses. Single-flight refs prevent double
POSTs; AbortController cancels local waiting, not a server-side operation. An
interrupted POST is UNKNOWN and never automatically retried. Local discard does
not revoke/refund server operations. Server session/source validation is final.
Countdown is based on an absolute <=60s expiry; submission checks the deadline.
Labels, headings, screen-reader live status/alerts, review/error/completion focus,
keyboard deliberate confirmation, disabled explanation, narrow-layout wrapping,
scoped visible focus and reduced-motion CSS preserve the existing dashboard.
Native facts distinguish attempted, initiated, response observed and persistence;
invalid/missing facts and missing cleanup cannot invent successful custody.
